# ADR 3 Интервалы дат и локальная проекция занятости

Статус: принято.

Проживание задаётся полуоткрытым интервалом `[startDate,endDate)`. Два интервала пересекаются, если `existing.start < requested.end` и `existing.end > requested.start`. Можно заселиться в день выезда другого гостя. Даты задаются без времени; граница текущего дня для серверных проверок - UTC. Продолжительность - от одних до 365 суток.

Поле rooms.available означает эксплуатационную доступность. Изменение его на false закрывает новые бронирования, но не удаляет ранее принятые. Занятость определяется активными строками `bookings` в Hotel, а не этим флагом. Центральные пользовательские бронирования хранятся в другой таблице `bookings` в базе Booking.

Hotel хранит проекцию, потому что при конкурентном подтверждении проверка пересечений и запись слота должны выполняться одной локальной транзакцией. Прямое чтение базы Booking нарушило бы самостоятельность сервисов и не обеспечило атомарную проверку.

Счётчик times_booked увеличивается один раз при успешном выделении слота. Повтор confirm не изменяет счётчик. При последующей отмене, включая компенсацию потерянного ответа, счётчик сохраняется: это историческое число успешных выделений, а не число действующих проживаний. Текущая загрузка считается отдельно по пересечению активных слотов с отчётным периодом.

Статистика считает физический номерной фонд за весь период, включая номера, которые сейчас на ремонте. История эксплуатационных состояний не хранится, поэтому из available нельзя достоверно восстановить прошлую доступную мощность. Загрузка отеля = занятые номеро-сутки / (число номеров × число суток периода). Нулевой номерной фонд даёт 0%.

H2 есть у двух сервисов с предметными данными. Eureka хранит реестр в памяти, Gateway использует реестр и конфигурацию; искусственные JPA-таблицы им не добавлены.
