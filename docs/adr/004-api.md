# ADR 4 Единая схема внешних маршрутов

Статус: принято.

В задании пути Booking приведены как пример и смешивают `/booking`, `/bookings`, `/user` с `/api/bookings/**` на Gateway. В реализации принята единая схема `/api/bookings` и `/api/users`, без алиасов. Она отражена в контроллерах, Gateway, OpenAPI, примерах и испытаниях.

Создание брони возвращает 201, повтор завершённого запроса - 200, повтор ещё выполняемой операции - 202. При удалённом отказе возвращается 503, при конфликте номера или requestId - 409. Запись неудачного бронирования остаётся в личной истории с CANCELLED и failureCode.

Идемпотентность бронирования определяется парой `(user_id,request_id)` и отпечатком значимых параметров. Для autoSelect поле roomId исключено из отпечатка; для ручного выбора не учитывается hotelId. Транспортный X-Request-Id обозначает отдельный HTTP-запрос и не заменяет ключ идемпотентности тела. Общая связь шагов - неизменный bookingId.

Удаление пользователя реализовано как деактивация, чтобы сохранить связь истории с владельцем. Отель с номерами и номер с историей не удаляются физически. Для такого номера используется available=false. Эти конфликты возвращают 409.
